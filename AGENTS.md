# AGENTS.md

## What this repo is

`shipping-manager` — a single-package Vite 8 + React 19 + TypeScript SPA managed with **pnpm**. The stack is already chosen and wired:

- **TanStack Router** (file-based routes in `src/routes`)
- **Tailwind CSS v4** + **shadcn/ui** (Base UI flavor, "base-nova" style)
- **Neon Auth** (email OTP) + Neon Data API via `@neondatabase/neon-js`

App state: Home (auth-gated), About, `/auth/$pathname` (Neon `AuthView`), `/account/$pathname` (Neon `AccountView`) and the business modules `/ordenes` (list), `/ordenes/$orderId` (detail and edit), `/nueva-orden`, `/clientes`, `/pagos` and `/configuracion`. `src/App.tsx` / `src/App.css` are dead template leftovers — `src/main.tsx` never imports them.

Deployed at **https://shipping.widvu.com** (GitHub Pages, custom domain at the site root).

## Commands

Use **pnpm** (`pnpm-lock.yaml` is the lockfile; no npm/yarn lockfiles).

- `pnpm dev` — dev server with HMR
- `pnpm build` — typecheck (`tsc -b`) then build (`vite build`); type errors fail the build
- `pnpm lint` — oxlint (config: `.oxlintrc.json`; ESLint is not used)
- `pnpm preview` — serve the production build

There is **no test framework configured**. Quick verification loop is: `pnpm lint && pnpm build`.

**Route-generation ordering quirk:** `src/routeTree.gen.ts` is generated by `@tanstack/router-plugin/vite`. `pnpm build` runs `tsc -b` *before* Vite regenerates the tree, so after adding/renaming a route file run `pnpm dev` once (or `pnpm exec vite build`) to regenerate the tree, then `pnpm build`. Otherwise `createFileRoute("/new/path")` fails typecheck.

## Routing (TanStack Router)

- Route files live in `src/routes`; the filename maps to the URL. `__root.tsx` is the layout (header + `<Outlet />` + devtools).
- `src/routeTree.gen.ts` is generated — never edit it by hand.
- Route module pattern: `export const Route = createFileRoute("/path")({ component: Page })`; read params with `Route.useParams()`.
- Use type-safe links, not literal URLs: `<Link to="/auth/$pathname" params={{ pathname: "sign-in" }} />`.
- Do **not** install `react-router-dom`. Neon's quickstart uses it, but this app is TanStack Router only and the Neon SDK is router-agnostic.

## Styling (Tailwind v4 + shadcn)

- `src/index.css` is the single global stylesheet and **must stay imported from `src/main.tsx`** — it was accidentally missing once, which silently disabled all Tailwind output (no CSS emitted in `dist`).
- Import order in `src/index.css` matters; keep Neon's Tailwind layer last:
  `tailwindcss` → `tw-animate-css` → `shadcn/tailwind.css` → `@fontsource-variable/noto-sans` → `@neondatabase/neon-js/ui/tailwind`.
- Tailwind v4 has **no `tailwind.config`**; theme tokens live in `@theme inline` plus `:root` / `.dark` CSS vars in `index.css`.
- `components.json`: style `base-nova`, base color olive, icon library lucide, CSS variables on. `src/components/ui` currently includes button, input, label, select, dialog, sheet, badge, card, avatar, combobox, calendar, popover, input-group and textarea. Add more with `pnpm exec shadcn add <component>` and rewrite generated `@/...` imports to relative paths.
- **This shadcn flavor is Base UI, not Radix** (`@base-ui/react`). There is no `asChild`:
  - compose with `render` + `nativeButton={false}` for button-like controls: `<Button nativeButton={false} render={<Link to="/auth/$pathname" params={{ pathname: "sign-in" }} />}>Iniciar sesión</Button>` (children on `Button` are preserved).
  - **For real navigation prefer `buttonVariants` on `Link`**, because Base UI sets `role="button"` on an anchor rendered through `Button`.
  - `buttonVariants` is exported for styling links directly.
- `cn` comes from the **`cn` npm package** (`src/lib/utils.ts` re-exports it); generated components import `cn` from `"cn"` directly.
- **No path aliases are actually wired.** `@/...` is declared only in the root `tsconfig.json` and `components.json`; `tsconfig.app.json` / `tsconfig.node.json` don't extend the root and `vite.config.ts` has no `resolve.alias`. Use relative imports inside `src/` (or wire both Vite and TS first).

## Auth (Neon)

- `.env` holds `VITE_NEON_AUTH_URL` and `VITE_NEON_DATA_API_URL`. `VITE_`-prefixed vars are public by definition. **`.env` is not in `.gitignore`** — decide before the first commit.
- `src/lib/neon.ts` builds the client with `BetterAuthReactAdapter` + a `dataApi` block and exports `neon`.
- `src/main.tsx` wraps the router in `<NeonAuthUIProvider emailOTP authClient={neon.auth}>` (import from `@neondatabase/neon-js/auth/react`).
- UI primitives (from `@neondatabase/neon-js/auth/react/ui`): `AuthView`, `AccountView`, `SignedIn`, `SignedOut`, `UserButton`, `RedirectToSignIn`.
- Route mapping:
  - `/auth/$pathname` → `<AuthView pathname={pathname} />`
  - `/account/$pathname` → `<AccountView pathname={pathname} />`
  - Valid auth pathnames: `sign-in`, `sign-up`, `forgot-password`, `reset-password`, `magic-link`, `email-otp`, `email-verification`, `two-factor`, `callback`, `recover-account`, `accept-invitation`, `sign-out`.
  - Valid account pathnames: `settings`, `security`, `teams`, `api-keys`, `organizations`.
- CSS: import the **Tailwind** entry (`@neondatabase/neon-js/ui/tailwind`), never `@neondatabase/neon-js/ui/css` (precompiled non-Tailwind variant — importing both duplicates styles). Neon's UI consumes the shadcn tokens (`--primary`, `--background`, …) with `--neon-*` fallbacks inside `@layer neon-auth`, so the app theme always wins.
- The SDK navigates with `window.location` (full page reloads) and takes a plain `pathname` string — that's why it works without a router adapter.
- Home is fully auth-gated by `<RedirectToSignIn />` outside `<SignedIn>`; remove it if the landing page must be public.
- The Neon SDK makes the main chunk ~1.1 MB; the build's ">500 kB chunk" warning is expected, not a regression.
- `__root.tsx` owns the signed-in shell: fixed `h-dvh` viewport, desktop `AppSidebar`, and `MobileAppHeader` below `md`. Keep route pages scrollable inside `main`, not the document body.

## Orders (`/ordenes`, `/nueva-orden`, `/ordenes/$orderId`)

- `settings.product_commission` is a **fixed amount per row** of `order_items`, not a percentage. `settings.stores` is a comma-separated string.
- `orders.products_total` is the **number of order rows**, not the sum of quantities or subtotals. The merchandise sum is derived in the UI and is not stored.
- `total_commission = products_total × product_commission`. `discount` is a percentage of `(merchandise_total + total_commission)`. `grand_total` subtracts that discount.
- Customer search uses the shadcn Combobox with a 300 ms debounce and stale-response protection.
- Creating saves the order at `/nueva-orden`; the list lives at `/ordenes` and the detail/edit screen at `/ordenes/$orderId`. The status filter defaults to all orders and includes an `active` grouping (`pending` + `partially_paid`).
- Payments are summarized by **original currency** (`payments.currency` + `original_amount`) so USD and VES never mix. Balance and credit use `base_amount`: `saldo = max(grand_total - paid_base, 0)` and `credit = max(paid_base - grand_total, 0)`.
- Status is edited manually, not derived from payments. Overpayment is allowed and shown as a credit.
- Creating inserts `orders`, recovers `order_id`, then inserts all `order_items`. If the details insert fails, the route deletes the just-created order to compensate (Neon Data API has no cross-table transaction here).
- Editing snapshots the order, deletes removed items, updates existing items, inserts new ones, then updates `orders`. Any failure restores the snapshot and reloads the detail with a notice; this is compensation, not a database transaction.
- Reusable order UI lives in `src/features/orders`. The creation and edit forms live entirely inside the viewport (`h-dvh` shell); only the product list scrolls. Below `lg`, their product rows render as stacked blocks. The order list switches from table to stacked rows below `xl` because the desktop sidebar leaves too little table width at intermediate sizes.

## Deploy (GitHub Pages)

- `.github/workflows/node.js.yml` deploys on every push to `master`: `pnpm install --frozen-lockfile` → `pnpm build` → `upload-pages-artifact` (`./dist`) → `deploy-pages`. Custom domain `https://shipping.widvu.com` is served at the **site root**, so Vite `base` stays the default `/` and emitted asset URLs are absolute (`/assets/...`).
- GitHub Pages is static-only: **there are no SPA rewrites**. Any deep link (e.g. `/auth/sign-in`) returns HTTP 404. This matters because the Neon Auth SDK navigates with `window.location` (login button, post-login redirects).
- Fix: `pagesSpaFallback()` in `vite.config.ts` copies the built `index.html` to `dist/404.html` from `closeBundle`. GitHub serves that file for every unmatched path, the app boots, and TanStack Router resolves the real `location.pathname`.
  - **Never reintroduce the classic `?/` 404 redirect trick** (the old `public/404.html`). The app doesn't parse `?/...`, so `RedirectToSignIn` loops forever between `/?/auth/sign-in` and `/auth/sign-in`.
  - Deep links responding **HTTP 404 with the app's HTML is expected** — don't "fix" it by switching to hash history (the SDK's full-page navigations use real pathnames).
- Post-deploy check: `curl -s https://shipping.widvu.com/auth/sign-in | grep -c 'id="root"'` → `1`.
- If real `200` statuses for deep links are ever required (SEO), move hosting to Cloudflare Pages / Netlify with `/* /index.html 200`.

## Toolchain quirks (easy to miss)

- **TypeScript ~7.0** with project references: `tsconfig.json` is a root shell referencing `tsconfig.app.json` (src) and `tsconfig.node.json` (vite.config.ts). `tsc -b` requires the root file; don't invoke `tsc` on a leaf config.
- **React Compiler is enabled** via Babel in `vite.config.ts` (`@rolldown/plugin-babel` + `reactCompilerPreset`). This slows dev/build and requires React Rules compliance (stable hooks order, no side effects in render).
- The date picker uses `react-day-picker` + `date-fns`. The shadcn Calendar is intentionally forced to 45 px day cells below `sm` so touch targets stay at least 44 px.
- **Vite 8 is Rolldown-based** — that's why the Babel plugin is `@rolldown/plugin-babel`, not the classic `@vitejs/plugin-react` Babel/ESBuild options.
- oxlint `react/only-export-components`: TanStack route files export `Route` + a component and will always warn. This is the accepted convention here (the template's `about.tsx` warns too) — don't "fix" it by splitting route files.
- Static assets go in `public/` (e.g. `icons.svg` referenced by URL) or imported from `src/assets/`.

## Smoke-testing without a browser

- `pnpm dev` + `curl -o /dev/null -w '%{http_code}' http://localhost:<port>/...` catches module-transform errors per route (200 = OK).
- To check a component's rendered HTML (e.g. shadcn + Base UI `render` composition), build it for SSR:
  `pnpm exec vite build --ssr <entry.tsx> --outDir .ssr-check && node -e "import('./.ssr-check/<entry>.js').then(m => console.log(m.render()))"`.
  The output dir must be **inside the repo** so Node resolves `react-dom`; delete it afterwards.
